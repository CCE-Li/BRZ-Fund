# BRZ Fund

以一个具体购车目标（二手 Subaru BRZ）为中心的个人财务管理应用。**数据全部保存在你自己浏览器的 IndexedDB 中**，不依赖后端、不需要注册登录、默认不联网。

## 这个应用解决什么问题

面向"生活费之外收入不稳定"的场景：生活费不自动算进购车基金，只有**真实到账**的钱才会增加余额，预计能赚到的钱永远不会被算成已有资金。应用负责回答三个问题：

1. 现在到底存了多少（购车基金 / 应急储备 / 未分配资金分别是多少）
2. 按真实的历史储蓄速度，大概什么时候能买上
3. 距离计划日期还差多少月储蓄

## 技术栈

| 层 | 选型 |
|---|---|
| 框架 | Vue 3 + TypeScript（严格模式） |
| 构建 | Vite |
| 状态 | Pinia（仅运行时状态，不作为数据库） |
| 路由 | Vue Router（Hash 模式，静态部署友好） |
| 图表 | Apache ECharts（按需引入，自写 `useECharts` 组合式封装） |

| 测试 | Vitest + fake-indexeddb + @vue/test-utils；Playwright 验收 |
| 样式 | 原生 CSS + CSS Variables（暗色为默认，可切浅色） |

## 目录结构与分层

```
src/
├── types/          # 领域模型与备份格式定义
├── utils/          # 金额定点运算、日期、CSV、校验结果类型
├── db/             # 数据库 schema、迁移、事务助手、连接与探针
├── repositories/   # 只负责 IndexedDB 增删改查，无业务规则
├── domain/         # 纯函数：余额、分配、储蓄速度、预测、一致性审计
├── services/       # 业务编排：跨表事务、状态机、备份恢复
├── stores/         # Pinia：运行时状态与水合
├── components/     # 可复用 UI / 图表 / 表单组件
├── views/          # 页面
└── styles/         # 设计令牌与基础样式
```

**分层铁律**：组件不直接访问 IndexedDB，不自行实现资金计算；所有余额由 `domain/balances.ts` 从交易流水聚合推导。

## 核心设计

### 金额与时间

- 所有金额以**整数分**（`Cents`）存储与运算，元→分使用字符串定点解析，避免浮点误差。
- 业务日期使用本地日历日 `YYYY-MM-DD`；创建/更新时间使用严格递增的 ISO 时间戳。

### 单一账本 + 资金桶

- 全部资金流动只有一张 `transactions` 表，7 种类型：收入 / 支出 / 桶间调整 / 转入购车基金 / 取出购车基金 / 转入应急金 / 取出应急金 / 其他调整。
- 资金被划分为四个桶：`unallocated`（未分配）、`brz`（购车基金）、`emergency`（应急储备）、`other`（其他用途）。
- **桶间移动永远不产生新收入**：转账在同一聚合器里同时扣减来源桶、增加目标桶。

### 预计收入 vs 实际收入

- 收入机会（Opportunities）里的 `estimatedGrossMin/Max` 属于**计划数据**，永远不会进入任何余额或储蓄速度计算。
- 只有通过"确认到账"登记的真实收入才会生成入账交易；每笔收入记录通过唯一索引保证**至多一条**入账交易，从存储层拦截重复记账。
- "已完成未付款"只改状态，余额不变；登记到账后机会自动推进为"已到账"。

### 分配（限额桶 + 可核销）

- 分配表示"这笔钱打算用于购车基金 / 应急金 / 其他"，写入 `allocations` 表，**不改变现金总额**。
- 单笔收入的分配总额不得超过「到账金额 − 直接成本」，超额分配在服务层与一致性审计两层拦截。
- 撤销分配会释放额度；作废收入时若仍有分配记录会被明确阻止，避免账目错乱。

### 预测的可解释性

- 储蓄速度取**最近 3 / 6 个已结束自然月**的均值，**空月份保留为 0**，不会为了好看而丢弃。
- 数据少于 3 个活跃月份、或平均速度为 0/负数时，明确显示"数据不足，暂时无法可靠预测"，绝不编造日期。
- 预测公式公开：`预计月份数 = ceil(剩余金额 ÷ 平均月储蓄)`，按自然月递推并处理月末收束。
- 情景模拟支持固定月储蓄与**按月单独输入**（适配季节性兼职）。

### 数据一致性

- 跨表写入（收入 + 交易、分配、导入恢复、清空）全部在**单个 IndexedDB 事务**内完成，失败整体回滚，界面不会误报成功。
- 提供一致性审计（Dashboard 展示）：重复入账、分配超额、孤立引用、负余额等。
- 交易金额与日期不可就地修改（要改就作废重建），保证账本可追溯。

## 数据安全与备份（务必阅读）

**IndexedDB 只是浏览器本地存储，不等于永久安全。** 以下情况数据都可能丢失：

- 手动"清除浏览历史 / 网站数据"
- 浏览器在磁盘压力下自动清理存储（未授予持久化许可时）
- 隐私 / 无痕模式：会话结束即清空
- **Safari：7 天无访问会清理脚本写入的存储**
- 更换浏览器、更换设备、重装系统、无痕窗口

因此：

1. 在设置页定期点击 **导出 JSON 备份**，并保存到网盘或另一台设备。
2. 应用会记录最近备份时间并提醒你；导入前会先校验文件结构与引用完整性，**校验失败不会改动现有数据**。
3. 设置页可以查看/申请浏览器的持久化存储许可（`navigator.storage.persist()`），但即便授予也不代表绝对安全。
4. 数据不会自动同步到其它设备或其它浏览器 —— 默认只存在当前浏览器的当前网站源下。
5. 应用不会上传任何财务数据，不接入任何银行接口，也不需要任何敏感凭据。

## 导入 / 导出

- **JSON**：完整业务数据（目标、机会、收入、交易、分配、快照、设置），导入采用"先校验 → 再事务覆盖提交"，保留原始 ID。
- **CSV**：收入记录与交易流水，带 UTF-8 BOM，可直接用 Excel 打开分析。

## 测试覆盖

```bash
npm test              # 单元 + 集成 + 组件测试（Vitest）
npm run test:e2e      # 端到端验收（Playwright，首次需 npx playwright install chromium）
```

- `tests/domain/`：余额聚合、分配额度、储蓄速度（含空月份）、预测（达成 / 零速 / 负速 / 超视界）、一致性审计、实体校验、Dashboard 视图模型。
- `tests/services/`：真实走 fake-indexeddb 的收入到账原子性、重复入账拦截、分配超额拒绝、作废回退、机会状态机、初始化向导、备份导出导入与无效数据拒绝。
- `tests/db/`：建库、迁移演练（v1→v2 保留数据）、事务失败整体回滚、withTransaction 原子提交。
- `tests/utils/`：金额定点运算与千分位解析、日期边界（闰年 / 月末 / 跨年）、CSV 转义。
- `tests/components/`：UI 组件的渲染、格式化、状态类名与无障碍契约。
- `tests/composables/`：五张图表的数据构造（空数据、作废过滤、系列拼接、目标线）。
- `e2e/`：真实浏览器中的验收流程，逐条对应 `docs/ACCEPTANCE.md` 的验收标准，
  包括关闭浏览器后重新打开数据仍在（持久化上下文）、注入写入失败不误报成功等。

> 已知工具链偏差：在 jsdom + Vite + Vue 3.5 组合下，SFC 编译出的原生事件处理器不会在合成事件中被调用（原生 `addEventListener` 正常，编译产物的处理器不触发）。因此组件测试只覆盖渲染与契约，**所有真实交互（表单输入、点击、刷新持久化）由 Playwright E2E 验证**，不在单测里伪造事件。

## 部署

纯静态站点：`vite.config.ts` 使用相对 `base`、路由使用 Hash 模式，因此构建产物 `dist/` 可部署到任意静态托管，
包括 GitHub Pages 的子路径（如 `https://<user>.github.io/BRZ-Fund/`）。

仓库内置 `.github/workflows/deploy.yml`：推送到 `main` 后自动执行
类型检查 → 单元测试 → 构建 → 发布到 GitHub Pages。
首次部署需要在仓库 Settings → Pages 中把 Source 设为 **GitHub Actions**。
